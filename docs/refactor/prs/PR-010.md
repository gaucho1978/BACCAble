**PR-010 — Ścisły parser SLCAN i odrzucanie zbyt długiej komendy**

Typ: **FIX**. Model: GPT-5.6 Sol / medium. Budżet produkcji: **300 linii**.

Wymagane dokumenty: [kontrakt](../EXECUTION_PL.md), [decyzje](../DECISIONS_PL.md), [akceptacja](../ACCEPTANCE_PL.md).

**Warunki wejścia:** [PR-008](PR-008.md). Bez dodatkowej bramki wejściowej; wymagany odbiór sprzętowy opisano poniżej.

**Problem i oczekiwany rezultat.** Skrócona komenda nie wykorzystuje poprzedniego bufora.

**Dozwolone pliki produkcyjne / narzędziowe.** `(nowy)` oznacza plik do utworzenia w tej karcie. Zmiana pliku wspólnego obejmuje tylko wskazaną odpowiedzialność.

- `firmware/ledsStripController/Core/Src/slcan.c`
- `firmware/ledsStripController/Core/Inc/slcan.h`
- `firmware/ledsStripController/USB_DEVICE/App/usbd_cdc_if.c`

**Dokładny zakres pracy.**

- Utrwalić długości istniejących opcodes; walidować len, hex, ID/DLC przed efektem. t/T/r/R uwzględniają długość ID i brak danych RTR.
- Propagować błąd can_tx; nie dodawać ACK/NACK do istniejącego dialektu.
- Po przekroczeniu SLCAN_MTU odrzucać do CR, nie traktować suffixu jako komendy.

**Poza zakresem.** Nowe opcodes, odpowiedź wersji, buforowanie TX USB.

**Kryteria akceptacji.** Wszystkie warunki wspólne oraz:

- [ ] PR-010-A1: 't1231AA', potem 't' → łącznie jedna wysłana ramka.
- [ ] PR-010-A2: Każde skrócenie i zły hex → błąd bez CAN/zmiany konfiguracji.
- [ ] PR-010-A3: Legalne maksymalne ID/DLC przechodzą; ponad limit/nadmiarowe bajty odrzucone.
- [ ] PR-010-A4: Przepełnienie + CR + poprawna komenda wykonuje tylko ostatnią; format RTR bez danych.

**Testy i dowody.** H:pr010, pełne H, B4, L, D i M. Wymagany profil przed akceptacją aktywnej zmiany: **HW-USB**.
