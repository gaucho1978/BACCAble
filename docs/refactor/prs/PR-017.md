**PR-017 — Obsługa poleceń UART poza przerwaniem**

Typ: **EXTRACT**. Model: GPT-5.6 Sol / medium. Budżet produkcji: **500 linii**.

Wymagane dokumenty: [kontrakt](../EXECUTION_PL.md), [decyzje](../DECISIONS_PL.md), [akceptacja](../ACCEPTANCE_PL.md).

**Warunki wejścia:** [PR-016](PR-016.md). Bez dodatkowej bramki wejściowej; wymagany odbiór sprzętowy opisano poniżej.

**Problem i oczekiwany rezultat.** RX callback przechwytuje dane, a funkcje aplikacji wykonuje main.

**Dozwolone pliki produkcyjne / narzędziowe.** `(nowy)` oznacza plik do utworzenia w tej karcie. Zmiana pliku wspólnego obejmuje tylko wskazaną odpowiedzialność.

- `firmware/ledsStripController/Core/Src/uart.c`
- `firmware/ledsStripController/Core/Inc/uart.h`
- `firmware/ledsStripController/Core/Src/main.c`

**Dokładny zakres pracy.**

- ISR składa legacy pakiet i kopiuje kompletny do kolejki RX o czterech slotach; odpowiedzi UART1 do osobnej kolejki małych zdarzeń.
- Przenieść obecny switch do process_uart_rx, przed periodic functions, limit czterech zdarzeń na iterację.
- saveToFilesystem/dynoToggle/zmiany map wykonują się tylko w main; pełna RX odrzuca nowy pakiet i liczy stratę.

**Poza zakresem.** CRC UART, semantyka poleceń i ekstrakcja funkcji samochodu.

**Kryteria akceptacji.** Wszystkie warunki wspólne oraz:

- [ ] PR-017-A1: Atrapy funkcji aplikacyjnych nigdy nie mają kontekstu ISR.
- [ ] PR-017-A2: Dwa pakiety są obsługiwane w kolejności po process_uart_rx.
- [ ] PR-017-A3: Piąty nie mieści się w czterech slotach, nie nadpisuje ich; licznik +1.
- [ ] PR-017-A4: Każdy legacy opcode ma bazowy wynik, przy maksymalnie czterech zdarzeniach/iterację.
