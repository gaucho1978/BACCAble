**PR-066 — Odświeżenia ekranu nie wypierają poleceń UART**

Typ: **FIX**. Model: GPT-5.6 Sol / medium. Budżet produkcji: **350 linii**.

Wymagane dokumenty: [kontrakt](../EXECUTION_PL.md), [decyzje](../DECISIONS_PL.md), [akceptacja](../ACCEPTANCE_PL.md).

**Warunki wejścia:** [PR-016](PR-016.md), [PR-042](PR-042.md). Bez dodatkowej bramki wejściowej; wymagany odbiór sprzętowy opisano poniżej.

**Problem i oczekiwany rezultat.** Kolejka zachowuje polecenia i tylko najnowszy niewysłany obraz.

**Dozwolone pliki produkcyjne / narzędziowe.** `(nowy)` oznacza plik do utworzenia w tej karcie. Zmiana pliku wspólnego obejmuje tylko wskazaną odpowiedzialność.

- `firmware/ledsStripController/Core/Src/uart.c`
- `firmware/ledsStripController/Core/Inc/uart.h`
- `firmware/ledsStripController/Core/Src/functions_C1baccable.c`

**Dokładny zakres pracy.**

- Dodać osobny pojedynczy pending slot dla BhBusIDparamString; jego aktualizacja zastępuje wyłącznie niewysłany obraz. Pozostałe polecenia używają istniejącej FIFO.
- Scheduler wybiera FIFO, jeśli niepusta; pending obraz tylko przy pustej FIFO. Zachować wszystkie terminy i okna półdupleksu; jawnie dopuszczamy opóźnienie ekranu przy ciągłych poleceniach.
- Nie scalać chime, toggle, write ani status responses. Raportować high-water/drop i liczbę zastąpionych obrazów.

**Poza zakresem.** Nowe bajty UART, szybsza magistrala, automatyczne retry toggle.

**Kryteria akceptacji.** Wszystkie warunki wspólne oraz:

- [ ] PR-066-A1: 100 kolejnych obrazów przed TX zajmuje jeden slot i wysyła ostatni.
- [ ] PR-066-A2: Polecenia A/B wysyłane FIFO przed pending obrazem.
- [ ] PR-066-A3: Aktywnego obrazu nie można zastąpić; nowe pending nie narusza active.
- [ ] PR-066-A4: Pełna FIFO odrzuca nowe polecenie z wynikiem, nie wypiera starego; brak dodatkowych transmisji poza oknem.

**Testy i dowody.** H:pr066, pełne H, B4, L, D i M. Wymagany profil przed akceptacją aktywnej zmiany: **HW-UART + HW-UI**.
